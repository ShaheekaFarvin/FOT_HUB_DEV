# 1. Backend Audit & Service Mapping (Phase 5)

## 1. Executive Summary

Phase 5 addresses the architectural coupling between the AI layer and the database by creating a **shared backend service layer** (`backend/services/`). 

Previously:
- Express REST Controllers (`studentController.js`, `adminController.js`) executed Mongoose queries directly.
- AI Chat Tool Executor (`backend/ai/tools/toolExecutor.js`) maintained duplicate direct Mongoose queries.

In Phase 5:
- All domain business logic is centralized in `backend/services/`.
- Both the Express REST Controllers and `toolExecutor.js` act as lightweight adapters that validate inputs and delegate execution to the shared services.
- Business rules, validation, and data boundaries are maintained in a single source of truth.

---

## 2. Tool ↔ Backend Service Mapping Contract

| AI Tool Name | Primary Business Operation | Shared Backend Service Method | Target Database Model / Collection | User Scope & Authorization |
|---|---|---|---|---|
| `searchAnnouncements` | Search active faculty notices | `announcementService.searchAnnouncements({ query, category, limit })` | `Announcement` | Public to all authenticated users |
| `checkVotingEligibility` | Check election eligibility by department | `electionService.checkStudentVotingEligibility(userContext, { electionId })` | `Election` | Department scoped (`userContext.department`) |
| `searchLostItems` | Search reported lost/found items | `lostFoundService.searchLostFoundItems({ query, type, category, limit })` | `LostFound` | Public active items |
| `submitComplaint` | Create student complaint | `complaintService.submitComplaint(data, userContext)` | `Complaint` | Bound strictly to `userContext._id` |
| `getComplaintStatus` | Lookup student complaint history | `complaintService.getUserComplaints(userContext, { complaintId })` | `Complaint` | Isolated strictly to `submittedBy: userContext._id` |
| `getNotifications` | Aggregate notifications & complaint updates | `notificationService.getUserNotifications(userContext, { unreadOnly })` | `Announcement` & `Complaint` | Personal complaint updates + public announcements |

## 3. Data Flow Architecture

```text
[ React UI / FOT Buddy ]
         │
         ▼
[ Express Router & Auth Middleware (JWT) ]
         │
         ▼
   ┌─────────────────────────────────────┐
   │         Authenticated req.user      │
   └───────────────┬─────────────────────┘
                   │
    ┌──────────────┴──────────────┐
    ▼                             ▼
[ REST Controllers ]      [ AI Orchestrator / toolExecutor ]
(studentController.js)    (toolExecutor.js)
    │                             │
    └──────────────┬──────────────┘
                   │
                   ▼
       [ Shared Service Layer ]
       ├── announcementService.js
       ├── complaintService.js
       ├── electionService.js
       ├── lostFoundService.js
       └── notificationService.js
                   │
                   ▼
         [ Mongoose Models ]
         └── MongoDB Atlas
```
