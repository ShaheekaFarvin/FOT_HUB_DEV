# Implementation Plan — Intent Routing

Build and formalize **Intent Routing**,The Intent Router receives a user message, normalizes and validates it, and routes it to a standardized intent representing one of the pre-established capabilities (or `UNKNOWN`), without executing any operation, querying databases, or calling Gemini APIs.

---

## User Review Required

> [!IMPORTANT]
> The router is strictly deterministic and lightweight. It operates standalone without Gemini API calls, MongoDB queries, or external network requests.
>
> 1. **Output Contract**: Standardized object format `{ intent: "<INTENT_NAME>" }`.
> 2. **Supported Intents**:
>    - `ANNOUNCEMENTS` (maps to `searchAnnouncements`)
>    - `VOTING_ELIGIBILITY` (maps to `checkVotingEligibility`)
>    - `LOST_AND_FOUND` (maps to `searchLostItems`)
>    - `SUBMIT_COMPLAINT` (maps to `submitComplaint`)
>    - `COMPLAINT_STATUS` (maps to `getComplaintStatus`)
>    - `NOTIFICATIONS` (maps to `getNotifications`)
>    - `UNKNOWN` (unsupported requests, empty, or invalid input)
> 3. **Input Handling**: Performs structural validation and trims surrounding whitespace. Null, undefined, empty, or non-string inputs safely resolve to `{ intent: "UNKNOWN" }` without throwing exceptions.

## Proposed Changes

### AI Orchestrator - Intent Routing

#### [MODIFY] [intentRouter.js]

Refactor `backend/ai/routing/intentRouter.js` to implement deterministic intent detection:
1. Define comprehensive keyword patterns for each intent category:
   - `COMPLAINT_STATUS`: matches phrases like `"status of my complaint"`, `"complaint status"`, `"check my complaint status"`, `"track complaint"`. Must take precedence over general `SUBMIT_COMPLAINT` keywords to avoid misrouting status queries.
   - `SUBMIT_COMPLAINT`: matches phrases like `"submit a complaint"`, `"report a problem"`, `"report a complaint"`, `"file a complaint"`, `"complain"`.
   - `ANNOUNCEMENTS`: matches `"announcement"`, `"announcements"`, `"notice"`, `"notices"`, `"faculty news"`.
   - `VOTING_ELIGIBILITY`: matches `"can i vote"`, `"voting"`, `"election"`, `"eligible to vote"`, `"voter"`.
   - `LOST_AND_FOUND`: matches `"lost item"`, `"lost my"`, `"find a lost"`, `"found item"`, `"lost & found"`, `"lost and found"`.
   - `NOTIFICATIONS`: matches `"notification"`, `"notifications"`, `"unread alerts"`, `"my notifications"`.
2. Implement structural input validation:
   - Check if input is a non-empty string after `.trim()`.
   - Return `{ intent: 'UNKNOWN' }` for `null`, `undefined`, `""`, or non-string inputs.
3. Return exact contract `{ intent: "<INTENT_NAME>" }`.
4. Export `{ routeIntent }` to preserve project modular conventions.
