# 2. Tool Call Detection

Implement Tool Call Detection to inspect Gemini's response, identify whether Gemini returned a normal text response or requested a function/tool call, extract and normalize tool names and arguments into a standardized internal representation, validate tools against the Tool Registry, and handle malformed requests safely without executing any tools.


### Backend AI Module

#### [NEW] [toolCallDetector.js]
- Export `detectToolCall(geminiResponse)`.
- Inspect `@google/genai` response object (`response.functionCalls` or candidate content parts) for tool call requests.
- Standardized Internal Output Contract:
  - **Function Call Detected**:
    ```javascript
    {
      isToolCall: true,
      toolCall: {
        name: "checkVotingEligibility",
        arguments: {}
      }
    }
    ```
  - **Normal Text Response**:
    ```javascript
    {
      isToolCall: false,
      toolCall: null
    }
    ```
  - **Unknown / Malformed Tool Call**:
    ```javascript
    {
      isToolCall: false,
      toolCall: null,
      error: "Unknown tool: deleteStudentRecords"
    }
    ```
- Validation Rules:
  - Verify function name against `getAvailableTools()` in `toolRegistry.js` (single source of truth).
  - Reject unregistered tools with controlled error message (`error: "Unknown tool: <name>"`).
  - Normalize missing/empty arguments to `{}`.
  - Reject invalid non-object argument types (e.g. string or array arguments) safely.
  - Safely handle `null`, `undefined`, or empty response objects without crashing.
  - **Strict Boundary**: Perform NO tool execution, database queries, memory updates, or Gemini follow-up calls.

#### [NEW] [testToolCallDetector.js]

Implement all 10 required test scenarios:

9. **Test 9 — Tool Name Integrity**: Verify returned tool names match exact registry names.
10. **Test 10 — Zero Execution**: Confirm no tool executor or MongoDB logic is invoked.
