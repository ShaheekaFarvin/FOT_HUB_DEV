# 2. Embedding Generation

This document outlines the implementation plan for **Embedding Generation** in Phase 4 of FOT Hub. The goal of this task is to convert the normalized **Retrieval Documents** prepared in Topic 1 into dense vector embeddings using Google Gemini's Embedding API.

---

```text
Retrieval Document (Topic 1)
       ↓
   document.content
       ↓
Embedding Service (text-embedding-004)
       ↓
Embedding Vector [768 floats]
```

---

## Topic 2.1 — Select the Embedding Model

Before building the embedding service, the provider, model, and vector dimensionality are explicitly defined:

| Parameter | Selected Specification | Rationale |
| :--- | :--- | :--- |
| **Embedding Provider** | Google Gemini (`@google/genai`) | Matches existing project dependency (`@google/genai` v2.15.0 in `backend/package.json`). |
| **Embedding Model** | `text-embedding-004` | Google's latest production text embedding model. High retrieval accuracy for semantic search. |
| **Output Dimensions** | **768** | Standard dense vector output dimension for `text-embedding-004`. Used for configuring MongoDB Vector Search index in Topic 3. |
| **Task Types** | `RETRIEVAL_DOCUMENT` (for knowledge indexing)<br>`RETRIEVAL_QUERY` (for runtime search queries) | Explicit task type configuration supported by Gemini API to optimize vector representations for retrieval. |

---

## Topic 2.2 — Create Embedding Service

Create a dedicated service component:

`backend/ai/knowledge/embeddingService.js`

### Responsibilities
- Accept normalized retrieval text (or query string).
- Initialize `GoogleGenAI` client using `process.env.GEMINI_API_KEY`.
- Call `client.models.embedContent({ model: 'text-embedding-004', contents: text, config: { taskType } })`.
- Validate the returned vector (check array type, length === 768, non-null numeric floats).
- Handle API errors, missing environment variables, network failures, and rate limits gracefully.

### Strict Scope Boundaries
- ❌ Does **NOT** query MongoDB.
- ❌ Does **NOT** perform vector search or `$vectorSearch`.
- ❌ Does **NOT** invoke Gemini chat models (`generateContent`).
- ❌ Does **NOT** modify controllers, middleware, or routes.

---

## Topic 2.3 — Generate Embeddings for Prepared Documents

A controlled, safe pipeline transforms Topic 1 Knowledge Documents into Vectorized Documents:

```text
Knowledge Document (Topic 1)
      ↓
document.content
      ↓
embeddingService.generateEmbedding(content)
      ↓
embedding: [0.0123, -0.0456, 0.0789, ... 768 float values]
```

### Privacy & Data Strictness
- **ONLY** the clean, normalized `content` string generated by Topic 1 (`KnowledgeDocumentBuilder`) is passed to `embeddingService`.
- Raw database ObjectIds (`_id`), internal schema metadata (`__v`), user passwords, createdBy references, and sensitive voter logs (`votes` array) are **NEVER** sent to the embedding model.

## Proposed Changes

### AI Knowledge Module

#### [NEW] [`embeddingService.js`]
Location: `backend/ai/knowledge/embeddingService.js`
- `generateEmbedding(text, taskType = 'RETRIEVAL_DOCUMENT')`: Generates a 768-dimensional float vector for a given text using `text-embedding-004`.
- `generateBatchEmbeddings(texts, taskType = 'RETRIEVAL_DOCUMENT')`: Batch wrapper for generating embeddings across multiple document strings safely.

#### [NEW] [`vectorizedKnowledgeBuilder.js`]
Location: `backend/ai/knowledge/vectorizedKnowledgeBuilder.js`
- `buildVectorizedDocument(record, source)`: Orchestrates Topic 1 `buildKnowledgeDocument` and Topic 2 `generateEmbedding` to output a complete Vectorized Knowledge Document.
- `buildVectorizedBatch(records, source)`: Batch generator processing raw MongoDB arrays into fully vectorized documents.
