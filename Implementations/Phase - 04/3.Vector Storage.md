# 3. Vector Storage / MongoDB Index

This document outlines the implementation plan for **Vector Storage & MongoDB Indexing** in Phase 4 of FOT Hub. The goal of this task is to establish a dedicated vector storage schema in MongoDB, create a repository for managing knowledge documents, build a pipeline script to index eligible campus records, and define the MongoDB Atlas Vector Search index configuration.

---

```text
Source MongoDB Records (Announcement, Election, LostFound)
       ↓ (Topic 1)
Knowledge Document Builder
       ↓ (Topic 2)
Embedding Service (text-embedding-004, 768-dim)
       ↓ (Topic 3)
KnowledgeRepository → MongoDB (`KnowledgeDocument` Collection)
       ↓
MongoDB Vector Search Index (`vector_index`)
```

---

## Topic 3.1 — Decide Storage Strategy

To decouple AI retrieval operations from live business models:
- **Dedicated Collection**: A separate Mongoose collection (`knowledgedocuments` via `KnowledgeDocument` model) is created.
- **Zero Schema Pollution**: Existing collections (`Announcement`, `Election`, `LostFound`) remain untouched without vector field bloat.
- **Controlled RAG Storage**: Keeps operational transaction data isolated from vector search indexes.

---

## Topic 3.2 — Define Knowledge Document Schema

Create a dedicated Mongoose model:

`backend/models/KnowledgeDocument.js`

### Schema Definition
```javascript
const mongoose = require('mongoose');

const knowledgeDocumentSchema = new mongoose.Schema({
  source: {
    type: String,
    enum: ['announcement', 'election', 'lostFound'],
    required: true,
    index: true,
  },
  sourceId: {
    type: String,
    required: true,
    index: true,
  },
  title: {
    type: String,
    required: true,
    trim: true,
  },
  content: {
    type: String,
    required: true,
  },
  metadata: {
    type: mongoose.Schema.Types.Mixed,
    default: {},
  },
  embedding: {
    type: [Number],
    required: true,
    validate: {
      validator: (v) => Array.isArray(v) && v.length === 768,
      message: 'Embedding vector must be an array of exactly 768 numbers.',
    },
  },
}, { timestamps: true });

// Compound index to ensure uniqueness per source record
knowledgeDocumentSchema.index({ source: 1, sourceId: 1 }, { unique: true });

module.exports = mongoose.model('KnowledgeDocument', knowledgeDocumentSchema);
```

## Topic 3.3 — Create Knowledge Repository

Create the data abstraction layer for saving, updating, and querying knowledge documents:

`backend/ai/knowledge/knowledgeRepository.js`

### Responsibilities & Functions
- `upsertDocument(doc)`: Saves or updates a normalized vectorized document in MongoDB using `source` + `sourceId` compound identity key.
- `upsertBatch(docs)`: Bulk upserts multiple vectorized documents using MongoDB `bulkWrite` operations.
- `getBySourceId(source, sourceId)`: Retrieves a specific knowledge record by source identity.
- `deleteBySourceId(source, sourceId)`: Removes a knowledge document when a source item is deleted/deactivated.
- `countDocuments(filter)`: Returns current total count of indexed knowledge documents.

## Topic 3.4 — Build Knowledge Indexing Process

Create a batch synchronization script:

`backend/scratch/indexKnowledgeData.js`

### Pipeline Execution Flow
```text
1. Connect to MongoDB Atlas
2. Query eligible records:
   - Announcement (isActive: true)
   - Election (status in ['upcoming', 'ongoing', 'completed'])
   - LostFound (status: 'active')
3. Transform via KnowledgeDocumentBuilder (Topic 1)
4. Generate 768-dim vectors via EmbeddingService (Topic 2)
5. Bulk upsert into KnowledgeDocument collection (Topic 3)
6. Output indexing summary report (inserted, updated, skipped, errors)
```

## Topic 3.5 — Create MongoDB Vector Search Index

Define the MongoDB Atlas Vector Search index definition targeting the `embedding` field in `knowledgedocuments` collection:

### Index Name: `vector_index`
### Database/Collection: `fot_hub.knowledgedocuments`

```json
{
  "fields": [
    {
      "type": "vector",
      "path": "embedding",
      "numDimensions": 768,
      "similarity": "cosine"
    },
    {
      "type": "filter",
      "path": "source"
    },
    {
      "type": "filter",
      "path": "metadata.category"
    },
    {
      "type": "filter",
      "path": "metadata.status"
    },
    {
      "type": "filter",
      "path": "metadata.type"
    }
  ]
}
```
