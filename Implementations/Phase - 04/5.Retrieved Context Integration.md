# 5. Retrieved Context Integration

This document outlines the implementation plan for **Retrieved Context Integration** in Phase 4 of FOT Hub. The goal of this task is to take the semantically retrieved knowledge documents from Topic 4, format them into controlled context blocks, inject them into the AI Prompt Builder, and add strict RAG grounding instructions so Gemini generates accurate, context-grounded responses without hallucinating.

---

```text
User Question + Retrieved Documents (Topic 4)
                 ↓ (Topic 5.1)
  Formatted Knowledge Context Block
                 ↓ (Topic 5.2 & 5.3)
Prompt Builder (System + Grounding + User + History + Tools + Knowledge Context)
                 ↓ (Topic 5.5)
           Grounded Prompt
```

---

## Topic 5.1 — Define Retrieval Context Format

Raw MongoDB records or complex JSON payloads are never passed to Gemini. Retrieved knowledge results from Topic 4 are formatted into clean, human-readable text blocks:

### Single Result Format
```text
Retrieved Knowledge:

[Source: Announcement]
Title: Assignment Submission Deadline Extended
Content:
The submission deadline for ICT3202 has been extended by 3 days.
```

### Multiple Results Format
```text
Retrieved Knowledge:

--- Result 1 ---
Source: Announcement
Title: Assignment Submission Deadline Extended
Content:
The submission deadline for ICT3202 has been extended by 3 days.

--- Result 2 ---
Source: Election
Title: Faculty Student Representative Election
Content:
Election Title: Faculty Student Representative Election
Election Type: Department Level
Department: ICT
Candidates:
- Name: Nimal Perera, Position: President, Manifesto: Focus on lab facilities
```

### Empty Retrieval Format
```text
Retrieved Knowledge:
(No relevant campus knowledge documents were retrieved from the database for this query.)
```

## Topic 5.2 — Extend Prompt Builder

Update `backend/ai/prompt/promptBuilder.js` to integrate `retrievedKnowledge` as a first-class contextual section alongside existing Phase 2/3 prompt inputs.

### Prompt Builder Architecture
```text
Prompt Builder
│
├── System Instructions (with RAG Grounding Rules)
├── Current User Context
├── Conversation History
├── Available Tools
├── Retrieved Knowledge   ← NEW (Topic 5)
└── Current User Message
```

---

## Topic 5.3 — Add RAG Grounding Instructions

Extend the `SYSTEM_ROLE` definition in `promptBuilder.js` with strict RAG grounding rules:

```text
# RAG GROUNDING RULES (RETRIEVED KNOWLEDGE)
1. Use Retrieved Knowledge: When answering questions about faculty announcements, elections, lost & found items, or campus events, rely primarily on the information provided in the "Retrieved Knowledge" section.
2. Fact Strictness: Do NOT invent, assume, or fabricate facts, dates, names, or policies that are not supported by the retrieved knowledge or live tool results.
3. Information Absence: If the retrieved knowledge does not contain the answer to the user's question, state politely that the available faculty information does not contain the answer, and suggest checking with the faculty office.
```

---

## Topic 5.4 — Define Empty Retrieval Behavior

When semantic search returns an empty array `[]` (no document met the similarity threshold):
- No fake or hallucinated context is injected into the prompt.
- The `Retrieved Knowledge` section explicitly states that no matching knowledge was found.
- Grounding rules instruct Gemini to politely inform the user that no records were found rather than inventing an answer.
