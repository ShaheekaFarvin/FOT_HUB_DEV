# 4. Semantic Retrieval

This document outlines the implementation plan for **Semantic Retrieval** in Phase 4 of FOT Hub. The goal of this task is to take a natural language user query, generate a query vector using Gemini's Embedding API, execute a `$vectorSearch` aggregate query against indexed MongoDB vector storage, apply score thresholding, and return clean, semantically relevant knowledge documents.

---

```text
User Query ("Was the ICT3202 deadline extended?")
    ↓ (Topic 4.1)
Query Embedding (embeddingService with taskType = 'RETRIEVAL_QUERY')
    ↓
Query Vector [768 floats]
    ↓ (Topic 4.2)
MongoDB Atlas $vectorSearch Aggregate Stage (`vector_index`)
    ↓
Score Projection & Thresholding (score >= similarityThreshold)
    ↓ (Topic 4.4)
Controlled Retrieval Results [{ source, sourceId, title, content, metadata, score }]
```

---

## Topic 4.1 — Create Query Embedding

Query embeddings are generated using the existing `embeddingService.js` created in Topic 2, specifying the `RETRIEVAL_QUERY` task type:

```javascript
// backend/ai/knowledge/embeddingService.js
const queryVector = await generateEmbedding(userQuery, 'RETRIEVAL_QUERY');
```

### Key Considerations
- Reuses `embeddingService.js` to keep embedding logic centralized without introducing redundant service layers.
- Task Type: `RETRIEVAL_QUERY` ensures optimal vector alignment with indexed documents embedded with `RETRIEVAL_DOCUMENT`.
- Output Dimension: Exactly **768** float values, perfectly matching stored `KnowledgeDocument` vectors.

---

## Topic 4.2 — Create Semantic Search Service

Create a dedicated service component:

`backend/ai/knowledge/semanticSearchService.js`

### Responsibilities
1. Accept natural language query string and optional filter/configuration options.
2. Call `embeddingService.generateEmbedding(query, 'RETRIEVAL_QUERY')` to produce the 768-dim query vector.
3. Construct and execute the MongoDB Mongoose aggregate pipeline using `$vectorSearch`.
4. Project relevance scores from `$meta: "vectorSearchScore"`.
5. Filter results against `SIMILARITY_THRESHOLD`.
6. Map raw aggregated documents into controlled result objects.

---

## Topic 4.3 — Define Search Parameters

Configurable parameters are centralized in configuration or default parameters within `semanticSearchService.js`:

| Parameter | Default Value | Rationale |
| :--- | :--- | :--- |
| `VECTOR_INDEX_NAME` | `"vector_index"` | Name of the MongoDB Atlas Vector Search index configured in Topic 3. |
| `TOP_K` | `5` | Maximum number of top relevant documents to retrieve per search query. |
| `NUM_CANDIDATES` | `50` | Number of candidate vectors evaluated by HNSW graph during Approximate Nearest Neighbor (ANN) search. |
| `SIMILARITY_THRESHOLD` | `0.65` | Minimum cosine similarity relevance score. Results below this score are filtered out to prevent low-relevance noise. |

---

## Topic 4.4 — Define Retrieval Result Format

`semanticSearchService.js` normalizes the aggregation output into a clean, controlled format:

```json
[
  {
    "source": "announcement",
    "sourceId": "507f1f77bcf86cd799439011",
    "title": "Assignment Submission Deadline Extended",
    "content": "Title: Assignment Submission Deadline Extended\nCategory: Academic\nPriority: high\nContent: The submission deadline for ICT 3202 has been extended by 3 days.",
    "metadata": {
      "category": "Academic",
      "priority": "high",
      "createdAt": "2026-08-10T10:00:00.000Z"
    },
    "score": 0.8742
  }
]
```

### Strict Output Guarantees
- Raw Mongoose documents, internal ObjectIds, `__v`, and vector arrays (`embedding`) are excluded from the result payload.
- Returns an empty array `[]` when no documents meet the `SIMILARITY_THRESHOLD`.

## Topic 4.5 — Test Semantic Retrieval

Create an automated test suite:

`backend/scratch/testSemanticRetrieval.js`

### Test Scenarios
1. **Semantic Match Test (Paraphrased Queries)**:
   - Query: `"What happened to the ICT3202 submission deadline?"`
   - Asserts match with Announcement document despite different wordings.
2. **Domain-Specific Queries**:
   - Query: `"Who are the candidates for the upcoming election?"` -> Returns Election knowledge document.
   - Query: `"Has anyone found a wallet near the library?"` -> Returns LostFound knowledge document.
3. **Low/No Relevance Query Test**:
   - Query: `"What is the recipe for chocolate cake?"`
   - Asserts return of clean empty array `[]` (score thresholding working).
4. **Controlled Result Format Test**:
   - Asserts every returned item has valid `source`, `sourceId`, `title`, `content`, `metadata`, and numeric `score`.
