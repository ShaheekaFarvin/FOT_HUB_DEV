# 6. RAG Controller Integration

This document outlines the implementation plan for **RAG Controller Integration** in Phase 4 of FOT Hub. The goal of this task is to seamlessly connect the semantic retrieval pipeline to the main AI Controller (`aiChatController.js`) via a dedicated `ragOrchestrator.js` service without breaking existing Phase 3 function calling, tool execution, conversation memory, or API contracts.

---

```text
POST /api/ai/chat
       ↓
aiChatController.js
       ↓
ragOrchestrator.js
 ├── Determine RAG Eligibility (Greeting vs Tool vs Knowledge)
 ├── IF Knowledge → Call semanticSearchService (Topic 4)
 ├── Format Context → contextFormatter (Topic 5)
 └── Build Grounded Prompt → promptBuilder (Topic 5)
       ↓
Gemini API (`gemini-3.5-flash-lite`) + Tool Declarations
       ↓
  ├── Tool Call Detected? → Execute Tool → Handle Tool Result → Gemini
  └── Direct Response? → Return Reply
       ↓
Save to Conversation Memory (`conversationMemory.js`)
       ↓
res.json({ reply })
```

---

## Topic 6.1 — Define When RAG Runs

Retrieval is executed selectively to avoid unnecessary latency, API calls, and noise:

### Decision Matrix

| User Message Category | Example | RAG Triggered? | Primary Handling Mechanism |
| :--- | :--- | :--- | :--- |
| **Greetings / Small Talk** | `"Hello"`, `"Good morning"`, `"Who are you?"` | ❌ **NO** | Direct Gemini generation via prompt instructions. |
| **User-Specific Operational Actions** | `"What's my complaint status?"`, `"Submit a complaint"`, `"Do I have notifications?"` | ❌ **NO** | Phase 3 Tools (`getComplaintStatus`, `submitComplaint`, `getNotifications`). |
| **User Voting Status Check** | `"Am I eligible to vote?"` | ❌ **NO** | Phase 3 Tool (`checkVotingEligibility`). |
| **Faculty Knowledge & Announcements** | `"What announcements discuss the exam schedule?"`, `"Tell me about the ICT 3202 deadline"` | ✅ **YES** | Phase 4 RAG Semantic Search. |
| **Election Candidate & Manifesto Info** | `"Who is running for President?", "What is Nimal's manifesto?"` | ✅ **YES** | Phase 4 RAG Semantic Search. |
| **Lost & Found Description Search** | `"Did anyone find a blue umbrella near Lab 02?"` | ✅ **YES** | Phase 4 RAG Semantic Search. |
| **General Faculty Inquiries** | `"What events are planned for this semester?"` | ✅ **YES** | Phase 4 RAG Semantic Search. |

## Topic 6.2 — Define RAG vs Tool Responsibility

The distinction between structured live operations and semantic knowledge retrieval is strictly preserved:

| Requirement | Mechanism | Rationale |
| :--- | :--- | :--- |
| **User-Specific Private Status** | Phase 3 Tool | Requires authenticated user ID filtering and live database query. Cannot be stored in global public knowledge vectors. |
| **Data Mutation Actions** | Phase 3 Tool | E.g. `submitComplaint` creates a new database record. RAG is read-only. |
| **Campus Knowledge Lookup** | Phase 4 RAG | Vector search over public announcements, election candidate manifestos, and lost/found descriptions. |

---

## Topic 6.3 — Integrate Retrieval via Orchestrator

Create a dedicated orchestrator layer to isolate search logic from HTTP controller logic:

`backend/ai/knowledge/ragOrchestrator.js`

### Responsibilities
1. Evaluate user query intent to decide if semantic retrieval should run.
2. If RAG eligible, execute `semanticSearchService.performSemanticSearch(currentMessage)`.
3. Pass retrieved documents to `contextFormatter.formatRetrievedKnowledge(results)`.
4. Pass formatted context, user details, conversation history, and tool declarations to `promptBuilder.buildPrompt(...)`.
5. Execute Gemini API call with function declarations active.
6. Handle tool call cycles if Gemini invokes a Phase 3 tool.
7. Save conversation turn to `conversationMemory.js`.
8. Return clean `{ reply: string }`.

### Controller (`aiChatController.js`) Role
`aiChatController.js` remains responsible for:
- Input validation (message length, empty check).
- Authentication verification (`req.user`).
- Calling `ragOrchestrator.processUserRequest(req.user, message)`.
- Sending HTTP JSON response (`res.json({ reply })`) or error status.

## Topic 6.4 — Preserve Phase 3 Functionality

Existing Phase 3 architecture is 100% preserved as a hard acceptance criterion:

- ✅ **Tool Registry & Declarations**: All Phase 3 tools (`searchAnnouncements`, `checkVotingEligibility`, `searchLostItems`, `submitComplaint`, `getComplaintStatus`, `getNotifications`) remain registered and available to Gemini.
- ✅ **Tool Call Detection**: `detectToolCall` continues to intercept function calls from Gemini.
- ✅ **Tool Executor & Result Handler**: `executeTool` and `handleToolResult` handle tool execution cycles seamlessly.
- ✅ **Conversation Memory**: `getHistory` and `addMessage` store user and assistant turns continuously across sessions.
- ✅ **API Contract**: The controller returns the exact existing JSON schema: `{ reply: string }`.
